# Root-cause digest — incident reports

Quarterly inventory of recurring root causes across `docs/incidents/`.

- Scope: `INC-0101`–`INC-0130` — 30 reports (incident dates 2026-01-01 to 2026-09-28)
- Generated: 2026-11-18
- Re-run: see [How to re-run](#how-to-re-run-quarterly)

All 30 reports map onto exactly **5 recurring root-cause patterns** (6 incidents
each). Every service in the corpus (checkout, search, billing-sync, notify-relay,
ledger-writer, gateway-edge) has been hit by every pattern once.

## P1 — Connection pool exhaustion under grown concurrency

The database connection pool stayed at its default size while concurrency grew,
so requests queued on pool acquisition until they timed out. Raising the pool
limit and adding an acquisition-timeout alert resolved it.

- Symptom: requests timing out under normal load.
- Representative incidents: INC-0101 (checkout), INC-0103 (billing-sync), INC-0106 (gateway-edge)
- All members: INC-0101, INC-0102, INC-0103, INC-0104, INC-0105, INC-0106

## P2 — Internal certificate expiry (renewal automation gap)

An internal service-mesh certificate quietly reached its expiry date. Renewal
automation covered only the public-facing certificates, not the service-mesh
ones, so mTLS handshakes began failing between internal services. Manual renewal
restored mTLS; coverage was added to the renewal job.

- Symptom: TLS handshakes failing between internal services.
- Representative incidents: INC-0107 (checkout), INC-0110 (notify-relay), INC-0112 (gateway-edge)
- All members: INC-0107, INC-0108, INC-0109, INC-0110, INC-0111, INC-0112

## P3 — Poison-message retry storm (no dead-letter routing)

Consumers could not keep up after one poison message forced repeated
redeliveries; the backlog grew until the queue-depth alarm fired. Dead-letter
routing for unprocessable messages stopped the retry storm.

- Symptom: message processing lagging hours behind real time.
- Representative incidents: INC-0113 (checkout), INC-0116 (notify-relay), INC-0118 (gateway-edge)
- All members: INC-0113, INC-0114, INC-0115, INC-0116, INC-0117, INC-0118

## P4 — Config drift from declared manifest

The deployed configuration had drifted from the declared manifest — a manual
hotfix months earlier changed a feature flag that was never written back, so
behavior diverged between staging and production with no code change.
Reconciling the manifest and adding a drift check to deploys closed the gap.

- Symptom: behavior diverged between staging and production with no code change.
- Representative incidents: INC-0119 (checkout), INC-0122 (notify-relay), INC-0124 (gateway-edge)
- All members: INC-0119, INC-0120, INC-0121, INC-0122, INC-0123, INC-0124

## P5 — Missing circuit breaker / bulkhead on external dependency

An upstream partner API began exceeding its latency SLO; our client had no
circuit breaker, so slow responses exhausted worker capacity and the failure
cascaded inward. A bulkhead plus breaker now isolates the dependency.

- Symptom: cascading failures rolling in from an external dependency.
- Representative incidents: INC-0125 (checkout), INC-0128 (notify-relay), INC-0130 (gateway-edge)
- All members: INC-0125, INC-0126, INC-0127, INC-0128, INC-0129, INC-0130

## Observations (not root causes)

- Every report's Detection section notes alert routing could have been faster —
  a standing secondary weakness independent of the five root causes.
- The root-cause section header is inconsistent across reports (`Root cause`,
  `What went wrong`, `Postmortem notes`, `Analysis`). The re-run tooling below
  handles all four; keep the variants in mind when writing new reports.

## How to re-run (quarterly)

The digest is generated by the cataloged cheaper workflow
`.cheaper/workflows/root-cause-digest.json`.

```bash
# Inspect the public contract
cheaper workflow interface .cheaper/workflows/root-cause-digest.json --cwd <workspace>

# Run with defaults (docs/incidents/*.md → reports/root-cause-digest.md)
cheaper workflow run .cheaper/workflows/root-cause-digest.json --cwd <workspace>

# Run with overrides (--input takes a file path or - for stdin)
cheaper workflow run .cheaper/workflows/root-cause-digest.json --cwd <workspace> --input - <<'EOF'
{"incidentPaths": ["docs/incidents/*.md"], "reportPath": "reports/root-cause-digest.md"}
EOF
```

- `incidentPaths` (optional, default `["docs/incidents/*.md"]`) — workspace-relative
  paths or globs to read.
- `reportPath` (optional, default `reports/root-cause-digest.md`) — workspace-relative
  output file.
- Outputs: `patterns` (structured pattern findings), `analysisSummary`,
  `reportSummary`.
- Prerequisites: a configured model provider (`cheaper auth status`); the run
  fails with `MODEL_TIER_UNAVAILABLE` when no provider is authenticated.
- Quarterly cadence: drop new `INC-*.md` files into `docs/incidents/` and re-run
  the command above — no other changes needed.
- Manual fallback (no provider): read each report's root-cause section (headed
  `Root cause` / `What went wrong` / `Postmortem notes` / `Analysis`), group by
  recurring cause into at most 5 patterns, list representative incident IDs per
  pattern, and update this file.
