# skill-claims (verification target, not a user feature)

The shipped skills under `packages/apm/.apm/skills/*/SKILL.md` are
prompt contracts full of assertions about CLI behavior: commands,
flags, envelope fields, error tables, JSON templates. This journey
extracts those claims and re-proves them against the real binary —
the deterministic layer of skill verification (firing/behavior is
model-dependent and out of scope here).

## Sub-features

- ` ```bash ` blocks in every SKILL.md execute and produce the claimed
  envelope shape
- Error tables: each `error.message` row reproduces on the real binary
  with the claimed `error.code`/exit
- JSON templates (workflow-create ships 5) pass
  `workflow interface` — `ok:true`, exit 0
- Distribution: `apm install` of `packages/apm` into a scratch dir
  lands all SKILL.md files per-target with parseable front matter

## How to get to it (user POV)

A maintainer changes a CLI flag or envelope field and must re-prove
that the skills still tell the truth — or reviews a PR that edited a
skill and wants evidence its examples run.

## Driving it with the CLI

```bash
# 1. extract every fenced bash/json block per skill
grep -n '```' packages/apm/.apm/skills/cheaper-workflow-create/SKILL.md
# pull each ```json template to $WS/tpl-N.json, then:
"$BIN" workflow interface "$WS/tpl-N.json" --cwd "$WS"   # each → ok:true

# 2. error-table rows: craft the minimal failing input per row
#    (see workflow-interface feature's negative battery for recipes)

# 3. distribution check
SCRATCH_INSTALL="$VROOT/apm-install"; mkdir -p "$SCRATCH_INSTALL"
cp packages/apm/apm.yml "$SCRATCH_INSTALL/"   # or point apm at the package
cd "$SCRATCH_INSTALL" && mise exec -- apm install --target agent-skills
find "$SCRATCH_INSTALL" -name SKILL.md | wc -l   # expect 7 under .agents/skills/
for f in $(find "$SCRATCH_INSTALL" -name SKILL.md); do
  head -4 "$f" | grep -q "name:" || echo "BAD FRONTMATTER: $f"
done
```

## Gotchas

- Check the **shipped** skill (`packages/apm/.apm/skills/`), not a
  sibling checkout's deploy copy (`.agents/skills/` is regenerated by
  `apm install` and can lag).
- Worker/model-backed commands in skill examples can't be executed
  without billable calls — verify those claims statically (flag exists
  in `--help`) and mark them `unverified-execution` in result.md.
- A claim that fails is a doc bug at file:line — report it; do NOT
  silently fix the skill inside a verification run.
